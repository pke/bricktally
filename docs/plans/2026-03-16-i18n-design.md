# i18n Integration Design

## Overview

Add internationalization to BrickTally with 11 locales using i18next. Pre-translated HTML at build time eliminates flash of untranslated content. Runtime i18next handles dynamic JS strings (modals, alerts, template literals).

## Locales

en, de, fr, es, nl, da, ja, ko, ru, zh-CN, zh-TW

## Architecture

### Hybrid: Build-time HTML + Runtime JS

- **Static HTML** (landing, footer, headers, placeholders, meta tags) — pre-translated per locale by a build script
- **Dynamic JS strings** (alerts, innerHTML, modals, badge generation) — `i18next.t()` at runtime with locale JSON embedded in the page

### Why Hybrid

- No flash of untranslated content (static HTML is pre-translated)
- No async fetch for translations (JSON embedded at build time)
- SEO: each locale has its own HTML with correct `lang`, meta tags, and content
- Dynamic strings can't be pre-translated (generated at runtime from user interaction)

## Translation Keys (~95 unique)

### Namespaces

| Namespace | Count | Examples |
|-----------|-------|---------|
| button.* | ~18 | cancel, delete, restore, backupAll, hideComplete |
| error.* | ~7 | noSetLoaded, invalidFormat, setNumberRequired |
| modal.* | ~8 | deleteTitle, restoreTitle, versionsTitle |
| display.* | ~12 | pieces, percentage, setInfo, noImage |
| section.* | ~5 | parts, spareParts, minifigures |
| landing.* | ~9 | heading, description, feature items |
| export.* | ~8 | badge, brickLink, pickABrick, textList |
| message.* | ~8 | complete, allPiecesAccounted |
| badge.* | ~6 | title, description, missingPieces |
| tooltip.* | ~4 | fillQuantity, toggleFullscreen |
| footer.* | ~3 | tagline, disclaimer |
| game.* | ~4 | title, moves, playAgain, youWon |
| meta.* | ~3 | title, description |

### Consolidation Applied

- "Please load a set first" (5 occurrences) → 1 key `error.noSetLoaded`
- "No missing pieces! Your set is complete." (3 occurrences) → 1 key `export.noMissingPieces`
- "Are you sure you want to reset..." (2 occurrences) → 1 key `confirm.resetSet`
- Piece counts use i18next pluralization: `badge.missingPieces_one` / `badge.missingPieces_other`
- Progress display uses interpolation: `display.pieces` = "{{completed}}/{{total}} pieces"

### Non-Translatable (Rebrickable API data)

Set names, part names, color names, minifigure names, years, part numbers — all served as-is from the API.

## Build Script (`scripts/build-i18n.js`)

For each locale:
1. Read `index.html` as template
2. Replace `data-i18n` attributes on static HTML elements
3. Replace `<html lang="en">` with correct locale
4. Replace SEO meta tags with translated values
5. Inject `<script>window.__LOCALE__ = "de"; window.__TRANSLATIONS__ = {...};</script>`
6. Write to `dist/<locale>/index.html`

Copy English to `dist/index.html` as default. Copy all other static assets unchanged.

## Runtime Initialization

```javascript
i18next.init({
  lng: window.__LOCALE__,
  fallbackLng: 'en',
  resources: {
    [window.__LOCALE__]: { translation: window.__TRANSLATIONS__ }
  }
});
var t = i18next.t.bind(i18next);
```

No async loading. Synchronous from embedded data.

## Usage Patterns

```javascript
// Simple key
alert(t('error.noSetLoaded'));

// Interpolation
html`<div>${t('display.pieces', { completed: 5, total: 10 })}</div>`

// Pluralization
t('badge.missingPieces', { count: missingCount })
// → "Missing 1 piece" or "Missing 3 pieces"
```

## Language Switcher

- Footer dropdown showing language names in their own script (Deutsch, Fran&ccedil;ais, &#26085;&#26412;&#35486;, etc.)
- On selection: `localStorage.setItem('locale', code)` and navigate to `/<locale>/`
- Preference persisted across visits

## Service Worker

- Precaches all locale-specific `index.html` files
- No separate locale JSON caching needed (embedded in HTML)
- `CACHE_VERSION` bumped by pre-commit hook as usual

## Changelog / What's New

- `changelog.json` stays English only
- What's New modal wrapper strings are translated (title, buttons, "See full changelog" link)
- Actual changelog entry content displays in English within the translated frame
- Full `/changelog` page stays English

## Fallback Behavior

- i18next `fallbackLng: 'en'` — untranslated keys show English, never raw keys
- Allows incremental rollout: ship with English complete, add languages progressively

## Existing Hooks

- Pre-commit `CACHE_VERSION` bump: unchanged, `sw.js` copied as-is
- Post-commit version stamp: needs update to stamp all `dist/*/index.html` copies

## i18next Loading

Vendored as `/js/i18next.min.js`, consistent with lottie and pako. No CDN dependency. Works offline via service worker precache.
